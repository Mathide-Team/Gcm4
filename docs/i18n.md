# Traductions (gettext)

Outil unique : `scripts/i18n-update.sh` (issue #165, même modèle que
Netcross).

| Commande | Effet |
|---|---|
| `scripts/i18n-update.sh` (`make i18n-update`) | `xgettext` (`_`, `N_`, `ngettext`, `pgettext`) → `lang/messages.pot`, puis `msgmerge` de chaque `lang/<locale>.po` (créé par `msginit` s'il manque), puis `msgfmt --check` |
| `scripts/i18n-update.sh --check` (`make i18n-check`) | N'écrit rien ; échoue si `messages.pot` ou un `.po` n'est plus à jour par rapport aux sources, si un `.po` est invalide, ou si `lang/LINGUAS` et `lang/*.po` divergent. Un `.po` est « à jour » quand ses chaînes actives (msgctxt/msgid/msgid_plural) sont exactement celles de `messages.pot` : les propositions approximatives (fuzzy) de `msgmerge` changent d'une version de gettext à l'autre et ne sont pas comparées |
| `scripts/i18n_report.py` (`make i18n-report`) | Taux de traduction par langue de `lang/LINGUAS` (traduites, fuzzy, vides) ; `--markdown` pour un tableau, ajouté au résumé du job CI |
| `scripts/i18n-update.sh --compile [DIR]` (`make translate`) | `.mo` dans `DIR/<locale>/LC_MESSAGES/gcm-lang.mo` (défaut `lang/`, lu par `bindtextdomain`) |

- **Langues** : `lang/LINGUAS` est la seule liste (29 langues).
- **Sources scannées** : fichiers Python suivis par git, hors `tests/`,
  `tools/`, `scripts/` et des sous-projets qui ont leurs propres catalogues
  (`SSH-Studio/`, `gtk-frdp/`).
- **Comparaisons** : `POT-Creation-Date` et `PO-Revision-Date` sont
  ignorées, ainsi que les coupures de lignes (deux versions de gettext ne
  coupent pas au même endroit) ; un `update` sans changement de chaîne ne
  modifie aucun fichier.
- **Aucune traduction automatique** : une nouvelle chaîne arrive avec
  `msgstr ""`. Une chaîne modifiée garde l'ancienne traduction marquée
  `#, fuzzy` (avec l'ancien `msgid` en `#|`), non utilisée tant qu'une
  personne ne l'a pas validée.
- **Domaine** : `gcm-lang` tant que le renommage (#99) n'est pas tranché ;
  `GCM_I18N_DOMAIN=gcm4 scripts/i18n-update.sh --compile` compile sous un
  autre nom.
- `tools/validate_po.py` reste le contrôle pre-commit/CI des `.po`.

## Ajouter une langue

1. Ajouter le code (ex. `es_ES`) dans `lang/LINGUAS`.
2. `make i18n-update` crée `lang/es_ES.po` (en-tête `Plural-Forms` rempli
   par msginit ; le script s'arrête s'il ne connaît pas la langue).
3. Traduire, puis `make translate` et committer `lang/es_ES.po` et
   `lang/es_ES/LC_MESSAGES/gcm-lang.mo`.

## Traduire

1. `make i18n-update` pour partir de catalogues à jour.
2. Ouvrir `lang/<locale>.po` (Poedit, Lokalize, GNOME Translation Editor ou
   un éditeur de texte) et remplir les `msgstr` vides.
3. Pour chaque entrée `#, fuzzy` : comparer l'ancien texte (`#| msgid`) au
   nouveau, corriger la traduction, puis **retirer la marque `fuzzy`** :
   tant qu'elle est là, la traduction n'est pas utilisée.
4. Garder les champs `{nom}` tels quels (ils sont remplis par
   `.format(nom=...)`) et le `_` des mnémoniques de menu (`_Fichier`).
5. `make translate`, vérifier dans l'application
   (`LANGUAGE=<locale> ./gnome_connection_manager.py`), `make i18n-report`
   pour le taux, puis committer le `.po` et le `.mo`.

## Règles pour le code

- Tout texte affiché passe par `_()` : `_("Connect")`. Les msgid sont en
  anglais.
- Valeurs variables : `_("{count} host(s) imported").format(count=n)`.
  Jamais `_(f"...")`, ni `_()` **dans** une f-string : selon sa version,
  xgettext ignore ou extrait ces appels, et une f-string n'est de toute
  façon jamais traduite (`tests/test_i18n_fstrings.py`).
- Les messages de journal (`logger.*`) ne sont pas traduits.
- Ne jamais énumérer les langues dans le code, un script ou un workflow :
  lire `lang/LINGUAS`.

`tests/test_i18n_garde_fous.py` (job Qualité) vérifie :

- l'absence de liste de langues hors `lang/LINGUAS` (collections Python de
  3 codes ou plus ; plus de 4 codes dans un script, un Makefile ou un
  workflow ; les `.md` peuvent citer des exemples) ;
- que chaque catalogue se compile, a son `.mo`, et qu'une locale absente
  retombe sur le texte source ;
- que les littéraux passés à `set_label`, `set_title`, `set_tooltip_text`,
  `set_placeholder_text`, `Gtk.Label(...)`, `Gtk.Button(label=...)`, etc.
  sont marqués `_()`. Seuls `plugins/pluginvnc2/`, `SSH-Studio/` et
  `gtk-frdp/`, sous-projets qui ont leur propre outillage, sont exclus.

## Régénération de l'issue #165

La première régénération a rattrapé l'écart entre l'ancien modèle (265
chaînes, généré en juin) et le code actuel (environ 830 chaînes, plugins
compris) : par langue, 212 traductions conservées telles quelles, 116
anciennes traductions proposées en `fuzzy` pour des chaînes modifiées, le
reste à traduire.

## Intégration continue

Le job **i18n (catalogues à jour)** de `.github/workflows/ci.yml` lance
`scripts/i18n-update.sh --check` (bloquant : une chaîne `_()` ajoutée ou
modifiée sans `make i18n-update` le fait échouer), compile toutes les
locales dans un dossier temporaire, puis publie le rapport de traduction
dans le résumé du job.
