# Traductions (gettext)

Outil unique : `scripts/i18n-update.sh` (issue #165, même modèle que
Netcross).

| Commande | Effet |
|---|---|
| `scripts/i18n-update.sh` (`make i18n-update`) | `xgettext` (`_`, `N_`, `ngettext`, `pgettext`) → `lang/messages.pot`, puis `msgmerge` de chaque `lang/<locale>.po` (créé par `msginit` s'il manque), puis `msgfmt --check` |
| `scripts/i18n-update.sh --check` (`make i18n-check`) | N'écrit rien ; échoue si `messages.pot` ou un `.po` n'est plus à jour par rapport aux sources, si un `.po` est invalide, ou si `lang/LINGUAS` et `lang/*.po` divergent. Un `.po` est « à jour » quand ses chaînes actives (msgctxt/msgid/msgid_plural) sont exactement celles de `messages.pot` : les propositions approximatives (fuzzy) de `msgmerge` changent d'une version de gettext à l'autre et ne sont pas comparées |
| `scripts/i18n-update.sh --compile [DIR]` (`make translate`) | `.mo` dans `DIR/<locale>/LC_MESSAGES/gcm-lang.mo` (défaut `lang/`, lu par `bindtextdomain`) |

- **Langues** : `lang/LINGUAS` est la seule liste (29 langues).
- **Sources scannées** : fichiers Python suivis par git, hors `tests/`,
  `tools/`, `scripts/` et des sous-projets qui ont leurs propres catalogues
  (`SSH-Studio/`, `gtk-frdp/`).
- **Comparaisons** : `POT-Creation-Date` et `PO-Revision-Date` sont
  ignorées, ainsi que les coupures de lignes (deux versions de gettext ne
  coupent pas au même endroit) ; un `update` sans changement de chaîne ne
  modifie aucun fichier.
- **Aucune traduction automatique** : une nouvelle chaîne arrive avec
  `msgstr ""`. Une chaîne modifiée garde l'ancienne traduction marquée
  `#, fuzzy` (avec l'ancien `msgid` en `#|`), non utilisée tant qu'une
  personne ne l'a pas validée.
- **Domaine** : `gcm-lang` tant que le renommage (#99) n'est pas tranché ;
  `GCM_I18N_DOMAIN=gcm4 scripts/i18n-update.sh --compile` compile sous un
  autre nom.
- `tools/validate_po.py` reste le contrôle pre-commit/CI des `.po`.

## Ajouter une langue

1. Ajouter le code (ex. `es_ES`) dans `lang/LINGUAS`.
2. `make i18n-update` crée `lang/es_ES.po` (en-tête `Plural-Forms` rempli
   par msginit ; le script s'arrête s'il ne connaît pas la langue).
3. Traduire, puis `make translate` et committer `lang/es_ES.po` et
   `lang/es_ES/LC_MESSAGES/gcm-lang.mo`.

## Régénération de l'issue #165

La première régénération a rattrapé l'écart entre l'ancien modèle (265
chaînes, généré en juin) et le code actuel (environ 830 chaînes, plugins
compris) : par langue, 212 traductions conservées telles quelles, 116
anciennes traductions proposées en `fuzzy` pour des chaînes modifiées, le
reste à traduire.
